1. Arquitetura do Sistema

O SecretStore é composto por três componentes que compartilham o mesmo banco de dados PostgreSQL:

┌─────────────────┐ ┌─────────────────────────┐ ┌──────────────┐ │ Programa │ │ Panel Admin │ │ PostgreSQL │ │ (.exe) │─────▶│ (Node.js/Express) │─────▶│ (Railway) │ │ Electron │ │ Railway Service │ │ │ └─────────────────┘ └─────────────────────────┘ └──────────────┘ │ │ ▲ │ │ │ └───────────────────────────┴─────────────────────────────┘ Todas as rotas /api/*
Componente Tecnologia Função
Panel Admin Node.js + Express + HTML/CSS/JS Gerenciar clientes, módulos, logs, resets
Programa .exe Electron + Python (PyInstaller) Interface do cliente - acessa módulos permitidos
Banco de Dados PostgreSQL (Railway) Armazenar admins, clientes, logs, sessões

3. Variáveis de Ambiente

Configure estas variáveis no serviço Panel Admin no Railway (Settings → Variables):

DATABASE_URL=${{Postgres.DATABASE_URL}}
ADMIN_EMAIL=admin@secretstore.com
ADMIN_PASSWORD=SuaSenhaForte@2025
ADMIN_NOME=Administrador
JWT_SECRET=seu-jwt-secret-64-caracteres-aqui
EMERGENCY_KEY=sua-chave-secreta-de-emergencia
PORT=8080
VariávelObrigatóriaDescrição
DATABASE_URLSimString de conexão PostgreSQL (Railway fornece automaticamente)
ADMIN_EMAILSimEmail do admin padrão criado no boot
ADMIN_PASSWORDSimSenha do admin (mínimo 8 caracteres, com maiúscula e especial)
ADMIN_NOMENãoNome exibido no painel (padrão: "Administrador")
JWT_SECRETSimChave para assinar tokens JWT (gere em generate-secret.vercel.app/64)
EMERGENCY_KEYSimChave para acessar rotas de emergência
PORTNãoPorta do servidor (Railway usa 8080 por padrão)

4. Deploy no Railway

Passo 1: Criar projeto no Railway

Acesse railway.app, crie um novo projeto vazio.

Passo 2: Adicionar PostgreSQL

Dentro do projeto, clique em + New → Database → PostgreSQL. Copie a DATABASE_URL gerada.

Passo 3: Adicionar o serviço Panel Admin

Clique em + New → GitHub Repo → selecione o repositório secretstore-panel-admin.

Passo 4: Configurar variáveis

No serviço criado, vá em Variables e adicione todas as variáveis listadas na seção 3.

Passo 5: Gerar domínio público

Vá em Settings → Networking → Generate Domain. O domínio será algo como:

https://secretstore-panel-admin-production.up.railway.app

Passo 6: Verificar deploy

Após o deploy ficar verde, acesse a URL. Você verá a tela de login do painel.

[DB] ✅ Itens de ajuda padrão criados

5. Painel Admin - Funcionalidades

Login

Acesse com o email e senha configurados nas variáveis ADMIN_EMAIL e ADMIN_PASSWORD.

Dashboard

Visão geral com estatísticas: clientes ativos/inativos, logins hoje, resets pendentes, uso de módulos.

Gerenciar Clientes

Criar, editar, bloquear/desbloquear clientes. Cada cliente recebe:

Campos: nome, email, senha, status, módulos permitidos.

Ações disponíveis por cliente:

AçãoDescrição
EditarAlterar nome, email, módulos, senha
Bloquear/AtivarAlterna o status entre ativo e inativo
Liberar DispositivoRemove o vínculo de device_id (permite login em outro PC)
Alterar SenhaDefine nova senha para o cliente
Aprovar ResetGera senha temporária quando o cliente solicita reset

6. Programa (.exe) - Configuração

Configurar URL da API

No arquivo api-client.js (raiz do projeto Electron), altere:

const API_BASE_URL = 'https://secretstore-panel-admin-production.up.railway.app';
⚠️ Sem barra no final! A URL não deve terminar com /.

Build do .exe

Opção 1: Execute build.bat (compila Python + Electron automaticamente).

Opção 2: Manual:

# Instalar dependências
npm install

# Compilar scripts Python
pyinstaller --onefile --noconsole scripts/mapas.py
pyinstaller --onefile --noconsole scripts/veiculos.py
pyinstaller --onefile --noconsole scripts/roupas.py
pyinstaller --onefile --noconsole scripts/peds.py
pyinstaller --onefile --noconsole scripts/weapons.py

# Build Electron
npx electron-builder --win portable

O executável será gerado em dist/SecretStore-Organizer-X.X.X.exe (~180 MB).

Fluxo do Cliente

1. Abre o .exe → tela de login.

2. Digita email e senha cadastrados pelo admin.

3. Se for primeiro login, o dispositivo é vinculado (device_id).

4. Vê apenas os módulos habilitados pelo admin (Mapas, Carros, Roupas, Peds, Weapons).

5. Se tentar logar em outro PC, será bloqueado (1 dispositivo por conta).

8. Rotas de Emergência

Essas rotas permitem desbloquear contas e resetar senhas sem precisar acessar o painel. Requerem a EMERGENCY_KEY configurada nas variáveis.

Verificar status de todos os usuários

GET /api/emergency/status?key=SUA_EMERGENCY_KEY

Retorna lista de admins e clientes com id, nome, email, status.

Desbloquear todos os usuários

GET /api/emergency/unlock?key=SUA_EMERGENCY_KEY

Define status = 'ativo' para todos os admins e clientes.

Resetar senha de qualquer usuário

GET /api/emergency/reset-password?key=SUA_EMERGENCY_KEY&email=EMAIL&newpass=NOVA_SENHA

Atualiza a senha (admin ou cliente) e define status como ativo.

⚠️ Segurança: Use uma EMERGENCY_KEY forte (mínimo 32 caracteres). Nunca compartilhe essa chave. Mude-a regularmente.

Exemplos práticos

# Ver status
https://secretstore-panel-admin-production.up.railway.app/api/emergency/status?key=minha-chave-123

# Desbloquear tudo
https://secretstore-panel-admin-production.up.railway.app/api/emergency/unlock?key=minha-chave-123

# Resetar senha do admin
https://secretstore-panel-admin-production.up.railway.app/api/emergency/reset-password?key=minha-chave-123&email=admin@secretstore.com&newpass=NovaSenha@2025

9. Solução de Problemas

Erro 401 - Unauthorized (login admin)

Causa: Senha incorreta ou bloqueio no localStorage do navegador.

Solução:

// No console do navegador (F12):
localStorage.clear();
location.reload();

Se persistir, use a rota de emergência para resetar a senha.

Erro 500 - Internal Server Error

Causa: Tabela ou coluna inexistente no banco.

Solução: Verifique os logs do deploy no Railway. Rode o SQL de criação de tabelas novamente se necessário.

Erro 502 - Bad Gateway

Causa: O servidor não iniciou corretamente (crash no boot).

Solução: Verifique os logs. Geralmente é DATABASE_URL ausente ou JWT_SECRET não definido.

"Sem conexão" no .exe

Causa: URL da API incorreta no api-client.js.

Solução: Verifique se a URL está correta e sem barra final. Teste no navegador: URL/api/health deve retornar JSON.

Cliente não consegue logar no .exe

Causa: Conta criada mas status inativo, ou device_id vinculado a outro PC.

Solução: No painel, verifique o status do cliente e libere o dispositivo se necessário.

CORS Error

Causa: O servidor não está permitindo requisições do domínio do frontend.

Solução: O server.js já usa cors() sem restrição. Se aparecer, reinicie o serviço.

CSP Error (Firebase scripts)

Causa: Referências antigas ao Firebase SDK no HTML.

Solução: Remova todas as tags <script> que apontam para gstatic.com/firebasejs/.

Tabela "usuarios" vs "clientes"

Causa: Código antigo referenciando tabela errada.

Solução: O sistema usa APENAS a tabela clientes. A tabela usuarios não deve existir. Se existir, delete-a:

DROP TABLE IF EXISTS usuarios CASCADE;
